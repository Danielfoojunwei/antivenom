# R1: current-Mac-only allocator-cache validation

The user selected the current Mac only after asking for speedups without
compromising results. This operational amendment is recorded before the
incident suite has produced any model outcomes. Preserve every original
scientific source, protocol and manifest byte-for-byte. The already running
E36–E38 queue is unchanged. Only the waiting incident queue is relaunched
through an explicitly recorded runtime wrapper.

Test MLX's **free allocator cache** cap of 256 MiB against its default. This
does not limit live tensors, model weights or the KV cache; it does not
truncate context, alter numerical precision, change generation parameters,
batch requests, share receiver outputs, or cache detector/answer results.
Every original method still performs its independent computation and its
actual uncached timing measurement. All sample sizes and analyses are fixed.

The wrapper waits for successful E36–E38 completion and the same shared model
lock through the original incident supervisor. Its first GPU child performs
the validation before running the original calibration script. Validation
uses only the original 20 NQ calibration IDs. Rank their actual captured-
excluded contexts by token count, choose shortest/median/longest, and use two
rounds with deterministically shuffled default/capped order (seed 17).
Prewarm CPU models and one short calibration case before timing. Each pass
extracts the captured signature and runs the actual frozen OR filter, refill
and greedy reader. Log raw extraction fields, NLI and attention vectors,
flags, context hashes, answers, memory use and times. Never access held-out
MemForm families or use answer correctness to select a runtime setting.

Require exact agreement of extracted question/claim, response, flags,
detector vectors and final context hashes between configurations in every
paired pass. Adopt the cap only if median paired total-runtime ratio is
<=0.95 and the aggregate runtime ratio is <=1.00. Otherwise retain the
default. These small calibration checks are an engineering selection rule,
not a scientific latency superiority result or a guaranteed speedup.

Freeze the validation inputs/code, choice and paired raw outputs before any
incident development inference. Every subsequent GPU child verifies those
hashes and uses the same selected configuration for every method, including
baselines. Save each child's runtime configuration and telemetry separately
without changing original scientific result schemas. The actual E43 timing
comparison remains uncached and within the same selected configuration.
Report the cache configuration with timing results, and do not pool it with
uncontrolled earlier hardware timings.

No additional model worker, paid service, hardware, smaller sample, precision
change, library upgrade or GPU batching is introduced. A failed validation
comparison selects the original configuration; a failure of the actual frozen
experiment remains a failure and is investigated rather than skipped.
